# Pilot failure-mode matrix

Core rule: **fail closed whenever incomplete, contradictory, stale or unavailable information could affect payroll handoff.** “Stop pilot?” means stop the affected automated path or the whole close-support pilot, never stop the customer’s established manual payroll process.

| Failure | Detection | Safe behavior | Human owner | Recovery | Stop pilot? |
|---|---|---|---|---|---|
| Mailbox permission revoked | OAuth/Graph/Gmail 401/403, failed health probe, last-success age exceeds threshold | Mark intake `STALE`; suppress completeness approval and reminders based on unseen mail; display manual fallback | Customer mail admin + workflow owner | Reauthorize the dedicated mailbox with approved scope; reconcile from last delta/history/provider ID; compare counts | **Affected path:** yes until reconciled. Whole pilot only if no manual route. |
| API unavailable/throttled | Timeout, 429/5xx, vendor status, stale sync timestamp | Keep last data visibly stale; no negative inference from missing records; Blueprint A/manual export remains source | Vendor contact + Sergio + owner | Bounded exponential backoff, honor `Retry-After`, later full reconciliation; switch to supported export/A | **B:** yes for approval. **A:** no if manual operation is safe. |
| Email/event duplicate | Same provider immutable ID/idempotency key; duplicate content flag for human review only | One workflow effect; append `DUPLICATE_IGNORED`; never duplicate reminder/case | Sergio for rule; operator for semantic ambiguity | Verify idempotency store and source thread; merge only by explicit human action | No, unless duplicates are not contained. |
| Email/event missed | Source count differs from queue; delta/history gap; periodic full reconciliation finds missing ID | Create/review missing record; do not claim complete while reconciliation is stale | Operator + Sergio | Fetch delta/history or bounded source window; full sync when provider requires; document cause | Yes at cutoff if unreconciled. |
| Attachment unreadable/protected/oversized/unsupported | MIME/type/size validation, parser error, protected-mail indicator | Do not execute, OCR or guess; store error metadata only; `NEEDS_REVIEW`; ask through approved template | Operator/reviewer | View safely in customer’s existing system; obtain structured form/resubmission; delete transient bytes | Only the case unless systematic. |
| Malicious attachment/link/macro | Malware scan/type mismatch/sandbox alert; active content detected | Quarantine outside app; never open automatically, execute macros or follow links; revoke exposed token if suspected | Customer security + Sergio | Incident process, clean resubmission through form/portal, audit containment | Yes for affected intake; whole pilot if compromise suspected. |
| Client sends incomplete data | Deterministic checklist has missing controlled item codes | `PARTIAL`; propose bounded approved reminder; never mark `APPROVED` | Case owner | Client supplies items; owner reviews; escalate at cutoff | No; this is normal workflow. | Client sends contradictory information | Conflicting values/source messages, operator flag, checklist invariant fails | `BLOCKED`; suppress reminders except approved clarification; no payroll handoff | Reviewer + customer client-contact owner | Resolve via approved corporate channel; record source and decision; do not overwrite history | Case: yes until human resolution. |

| Owner absent | Out-of-office, unacknowledged assignment SLA, no login/activity | Route to pre-named backup; no unowned reminders/handoffs | Workflow owner/backup | Reassign with audit; brief backup from queue/source links | No if backup exists; yes at cutoff without one. |

| Sheet/Excel concurrent edit or formula corruption | Protected-cell change, validation failure, duplicate version, formula/checksum test | Lock affected view; export snapshot; use source/audit/manual list; no approvals from corrupted rows | Customer file owner + Sergio | Restore prior version/copy, replay audit/source changes, strengthen protection | Yes for queue decisions until reconciled. |
| Unauthorized access/role escalation | Audit/admin alert, access review discrepancy, anomalous export/login | Revoke session/grant, freeze affected automation, preserve evidence; avoid deleting logs | Customer security/privacy + Sergio | Incident plan, credential rotation, scope review, impact assessment and controlled restore | Yes; whole pilot until containment/decision. |
| Data appears outside approved categories | Field scan/operator report/attachment content reveals salary, bank, ID, health, union, garnishment, etc. | Stop processing/copying; leave source in customer system; quarantine/delete transient copy per incident instruction | Privacy/security owner + reviewer | Security/legal review, re-minimize schema, obtain approval or remove data need | Yes for affected path; whole pilot if unavoidable. |
| Audit log unavailable or mutable | Write failure, sequence gap, integrity check or permissions test fails | Stop sensitive state transitions/reminder approvals; read-only operation/manual log only | Sergio + reviewer | Restore audit service/data, reconcile actions from provider/source, document gap | Yes for approval/send/handoff. |
| Backup fails or restore untested | Backup monitor failure, expired recovery window, failed rehearsal | Do not claim recoverability; export current queue; increase manual snapshots; no destructive changes | Sergio + customer owner | Enable paid backup, correct failure, restore-test separately | Conditional: stop before live close if no acceptable recovery. |
| Deployment outage | Health check/external probe fails, operators cannot load queue | Customer uses documented mailbox/portal/Sheet fallback; reminders suppressed; record outage window | Sergio + workflow owner | Roll back last deploy, restore service, reconcile all source events during outage | App path: yes; manual pilot can continue. |
| Bad deployment/configuration | Health/regression checks fail or metrics diverge after release | Keep/restore last known-good; no schema destructive action; disable affected job | Sergio | Code/config rollback; data repair only via reviewed migration/reconciliation | Affected path: yes. |
| Clock/timezone/cadence error | Candidate outside agreed business time/cutoff; UTC/local mismatch test | Suppress all reminder candidates; never infer cutoff from server timezone | Reviewer + Sergio | Correct explicit `Europe/Madrid`/customer timezone rules, rerun boundary tests, re-review candidates | Reminder path: yes. |
| Customer stops using workflow | Inputs bypass route, queue not reviewed, adoption/coverage metric falls | Stop automated reminders based on incomplete adoption; surface adoption gap; no fabricated ROI | Sponsor + workflow owner | Interview, retrain/configure once, or terminate/re-scope; return to manual process | Yes if adoption cannot meet measurement threshold. |
| Scope creep during close | New system/cohort/channel/exception category/request appears | Put out of scope; do not patch live; log change request | Sponsor + Sergio | Handle manually; estimate after close under separate approval | No for original scope; reject expansion. |

## Stop levels

- **Case stop:** one record is `BLOCKED`; other independent cases continue.
- **Path stop:** ingestion, reminder, LLM, ERP reconciliation or handoff path is disabled independently.
- **Pilot stop:** no trustworthy source/queue/audit/manual fallback; unauthorized/special-category exposure; unsafe requirement; systemic mapping/reminder error; or customer will not operate the workflow.

## Recovery acceptance

After any material failure, resume only when:

1. Cause and affected time/range are known.
2. Credentials/scope/integrity are verified.
3. Source-to-queue reconciliation is complete.
4. Duplicate/missed reminder risk is reviewed.
5. Synthetic regression test passes.
6. Workflow owner explicitly approves resume.
7. Incident, decision and any residual risk are recorded.
